Recurrences · gopay-js-sdk

sdk.createRecurrence(goid, params)

POST /eshops/{goid}/recurrences — store a payment template to create payments from. Nothing is charged and no payment exists yet. The returned id is auto-filled into every panel below.

—

recurrence_date_to is mandatory and must be a plain yyyy-MM-dd date — a value carrying a time component is rejected with 400. The schedule fields appear only for AUTO: an ON_DEMAND recurrence must not send a schedule at all, and the compiler enforces that too, since params is a discriminated union on type.

sdk.getRecurrence(recId)

GET /recurrences/{rec_id} — read the recurrence's state and the payment it carries. NEW after creation, REQUESTED once the first payment is waiting to be paid, STARTED once it was paid, STOPPED when it ended.

—

sdk.startRecurrence(recId, override?)

POST /recurrences/{rec_id}/start — create the first payment and move the recurrence to REQUESTED. Returns the payment, whose gw_url is rendered as a link below; the customer pays there.

—

The recurrence is not STARTED yet — it becomes so only once the customer actually pays this payment. Starting an already-started recurrence is rejected with 409.

sdk.awaitRecurrenceState(recId, options?)

Polls GET /recurrences/{rec_id} until the recurrence reaches STARTED or STOPPED. This is the supported way to wait for the customer to pay the first payment, which is what createNextPayment below is blocked on.

—

STOPPED resolves rather than rejects — it is a real outcome, and stop_reason says which. This panel passes timeoutMs: 60000; the SDK itself has no default timeout, since it is waiting on a human.

sdk.createNextPayment(recId, override?)

POST /recurrences/{rec_id}/next — create the next payment of a recurrence that is already STARTED. Overrides replace only the fields you send; customer is merged field by field rather than replaced.

—

Called before the recurrence is STARTED this answers 409 — run the await panel above first. An unknown field in the override is rejected with 400.

sdk.stopRecurrence(recId)

DELETE /recurrences/{rec_id} — stop the recurrence from creating further payments. Not a delete: it still reads back, in state STOPPED with stop_reason: CANCELLED_VIA_API. Returns void, so this panel reports the follow-up read instead.

—

Stopping an already-stopped recurrence is rejected with 409.
